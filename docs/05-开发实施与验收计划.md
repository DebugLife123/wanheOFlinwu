# 开发实施与验收计划

- 文档版本：`v0.2`
- 更新日期：`2026-08-02`

## 1. 实施策略

项目按可独立验证的业务闭环推进，不按页面数量平均分工。每个里程碑都必须具备代码、自动化测试、操作说明和可演示结果，未达到退出条件不进入正式试用。

核心业务范围已经确认，但实际仓库清单、序列号标签、历史数据样表、纸张样式和部署环境仍需样例验证。本计划使用里程碑和工作量等级，不承诺未经核实的具体上线日期；样例确认后再结合开发人数排期。

## 2. 开发基线

### 2.1 默认假设

- 单门店、多仓库/库位，并区分正常可售、样机、赠品、退回待检和损坏品。
- 管理员、用户两种角色；安装售后人员使用用户账号并可查看客户完整地址。
- 对需要追踪的商品逐台记录序列号、机身码或保修卡号。
- 历史商品、客户和订单数据迁移规模在 1 万条以内。
- 支持多次收款、欠款明细、销售单和安装单打印。
- 电脑和手机使用响应式 Web/PWA。
- 无在线商城、无在线支付、无复杂财务核算。
- 云端 Docker 部署为默认方案。

### 2.2 完成定义

一个功能只有同时满足以下条件才算完成：

- 需求编号和业务规则已经明确。
- 页面在电脑与手机目标宽度下可用。
- 服务端执行权限、输入和状态校验。
- 关键写入具备事务与审计记录。
- 单元/集成测试覆盖主要成功和失败路径。
- 关键流程有端到端测试。
- 无阻断性缺陷，并通过业务验收样例。
- 用户可理解错误提示，不暴露内部异常。

## 3. 里程碑

### M0：需求确认与原型

交付内容：

- 确认本套需求、业务流程、字段和状态。
- 收集真实商品、进货、销售、安装和售后样例。
- 完成手机与电脑关键页面线框/高保真原型。
- 确认部署方式、仓库清单、序列号标签、数据字段和打印样张。
- 建立需求追踪清单和变更记录。

退出条件：

- 店主确认 P0 范围和明确不做的内容。
- 10 笔真实销售样例与 5 笔进货样例可以被字段完整表达。
- 管理员和用户分别走查店内、安装、售后路径，没有阻断其工作的信息缺口。

### M1：工程基础与账号权限

交付内容：

- Next.js、TypeScript、数据库迁移和测试框架初始化。
- Docker 开发环境、配置管理和健康检查。
- 登录、退出、改密、账号停用和会话管理。
- 角色权限、接口错误格式、操作日志基础设施。
- 响应式应用框架、导航和 PWA 基础配置。

退出条件：

- 管理员与用户登录后只能看到各自授权导航和数据。
- 接口直接访问也能正确拒绝未授权操作。
- 停用账号和改密后旧会话按规则失效。
- 开发、测试和生产配置不混用秘密信息。

### M2：商品、供应商、多仓库、进货与库存

交付内容：

- 品牌、分类、商品、图片和供应商管理。
- 仓库/库位、库存类型、仓库调拨和类型转换。
- 进货单草稿、确认、指定仓库分批收货、关闭和作废。
- 库存现存量、在途量、流水、设备台账和低库存提醒。
- 序列号、机身码、保修卡号的逐台登记和唯一性校验。
- 样机、赠品、退回待检、损坏品和库存调整审计。
- 商品库存查询与 Excel 导出。

退出条件：

- 分批收货后，进货单状态、累计收货和库存完全一致。
- 重复提交收货请求不会重复增加库存。
- 普通用户不能无理由修改库存。
- 从任一库存数字可以追溯到来源流水和单据。
- 跨仓库调拨前后总库存一致，设备台账位置同步变化。
- 同一序列号或机身码不能重复收货、预留或出库。

### M3：客户、销售、收款、配送与安装

交付内容：

- 客户、多个地址、重复手机号提示和客户时间线。
- 销售订单创建、改价权限、确认、备货、指定仓库/设备出库和取消。
- 本店库存与厂家直发两种履约来源。
- 按仓库和设备的库存预留、并发防超卖和出库流水。
- 多次收款、收款方式、欠款余额、约定还款日期和跟进记录。
- 配送记录、安装任务和设备标识现场核对。
- 手机端快速开单、任务更新和图片上传。

退出条件：

- 两人同时购买最后一件商品时只有一单能够确认。
- 取消未出库订单正确释放预留。
- 已出库订单不能无痕取消或删除。
- 收款、配送和安装状态互不覆盖。
- 客户详情能完整展示订单、安装和收款摘要。
- 厂家直发不会改变本店库存，但能追踪供应商发货、送达和设备标识。
- 多次收款后欠款余额准确，作废错误收款后可以重新计算。

### M4：售后、报表、导出与运维

交付内容：

- 售后工单、负责人、状态、处理结果和附件。
- 首页待办和基础销售、库存、应收报表。
- 权限感知的 Excel 导出。
- 商品、客户、历史订单的 Excel 导入预览、错误报告和分批提交。
- 销售单、安装单的打印视图和 PDF 输出。
- 结构化日志、关键告警、自动备份和恢复说明。

退出条件：

- 可由手机号找到历史订单并创建售后工单。
- 报表数值能回查到订单或库存流水。
- 无成本权限的用户在页面、接口和导出中均看不到成本。
- 在独立环境完成一次数据库和附件恢复演练。
- 1 万条以内样例数据完成试导入，成功、失败和跳过数量可核对。
- 销售单和安装单按确认样式正确打印，且不泄露成本和利润。

### M5：店内试运行与上线

交付内容：

- 使用真实数据进行受控试运行。
- 编写管理员和用户操作手册，用户手册覆盖店内、安装和售后工作。
- 修复试运行缺陷，确认数据切换时间。
- 部署正式环境、HTTPS、监控和备份。
- 记录上线版本和回退方案。

退出条件：

- 店内实际用户完成核心流程并签字/明确确认验收。
- P0 缺陷全部关闭，非阻断问题有负责人和计划。
- 备份最近成功时间可见，恢复步骤已验证。
- 旧记录方式的停止时间和只读保存方式已确定。

## 4. 需求追踪与变更

每个开发任务关联需求编号，例如 `SALE-004`。测试用例、提交记录和验收记录使用同一编号，保证问题可以追溯。

新增需求按以下方式处理：

1. 说明要解决的真实场景和当前替代做法。
2. 判断属于 P0 修正、P1 增强还是 P2 以后考虑。
3. 记录对数据模型、权限、库存、历史数据和排期的影响。
4. 由店主确认是否替换当前范围中的其他工作。

这样可以把新增功能的机会成本说清楚：加一个非关键功能，通常意味着核心流程晚一些可用，而不是“顺手免费增加”。

## 5. 测试计划

### 5.1 单元测试

- 订单金额、优惠、收款状态计算。
- 可用库存和低库存判断。
- 仓库调拨、库存类型转换和总库存守恒。
- 序列号设备状态转换和唯一性校验。
- 订单、进货、安装和售后状态转换。
- 权限判断和敏感字段过滤。
- 单号生成和时区/日期规则。

### 5.2 集成测试

- 进货收货与库存流水事务。
- 订单确认、预留、出库、取消与库存事务。
- 并发确认最后库存的防超卖测试。
- 收款/退款记录与订单汇总。
- 欠款余额、约定日期和逾期状态。
- 厂家直发不影响本店库存的测试。
- Excel 导入分批事务、重复数据和错误报告。
- 用户停用、会话失效和导出权限。
- 冲销后原流水和反向流水的关联。

### 5.3 端到端测试

- 管理员创建账号和商品。
- 用户完成指定仓库进货并登记设备序列号。
- 管理员完成仓库调拨和样机转可售。
- 用户创建客户、销售订单并选择具体设备出库。
- 安装人员使用用户账号在手机端核对设备并完成安装任务。
- 用户通过手机号创建售后工单。
- 店主查看报表并导出。

### 5.4 兼容与视觉测试

- 电脑端：当前稳定版 Chrome、Edge。
- 手机端：常见 Android Chrome/微信内置浏览器；iPhone Safari 是否纳入目标需确认。
- 关键页面在窄屏、普通手机、平板和桌面宽度截图对比。
- 检查文字截断、按钮遮挡、表单键盘遮挡、表格溢出和弹窗滚动。

### 5.5 安全测试

- 未登录和越权访问接口。
- 修改请求 ID 访问其他客户/订单。
- 登录暴力尝试、会话固定和 CSRF。
- 文件类型伪造、超大上传和私有图片未授权访问。
- 导出敏感字段和公式注入风险。
- 日志中是否出现密码、Cookie 或令牌。

## 6. 业务验收场景

### UAT-01 完整进货

创建包含两个商品的进货单，分别进入两个仓库，第一次收一部分并逐台录入序列号，第二次收齐。核对进货单状态、在途量、分仓现存量、设备台账和两条收货记录。

### UAT-02 正常销售安装

为新客户创建需要配送安装的订单，从指定仓库选择具体设备，确认后检查预留，出库后检查库存，安装时核对设备标识，最后检查客户和设备时间线。

### UAT-03 订单取消

确认订单后在出库前取消，核对预留释放、订单历史和审计日志；确认普通用户不能把已出库订单直接取消。

### UAT-04 并发防超卖

商品可用库存为 1，两个账号同时确认各购买 1 件的订单。只能有一个成功，失败方得到明确提示，库存不为负。

### UAT-05 欠款与多次收款

订单设置约定还款日期并分两次收款，验证状态从未收变为部分收款再变为已收款，欠款余额、收款方式、金额汇总和操作人正确。

### UAT-06 售后追踪

使用客户手机号找到订单，创建售后工单，经过处理中、等待配件、已解决、已关闭，确认历史可追溯。

### UAT-07 权限与导出

管理员和用户分别访问成本、客户完整地址、用户管理、审计和导出，验证用户能处理地址相关业务但看不到成本、利润、账号和审计，页面与接口权限一致。

### UAT-08 备份恢复

生成包含商品、订单、流水和图片的备份，在独立环境恢复，核对记录数量、关键金额和附件可访问性。

### UAT-09 多仓库与特殊库存

把序列号商品从门店仓调拨到后仓，将一台样机转为可售，将赠品关联销售订单出库。核对调拨前后总库存守恒、设备位置和所有关联流水。

### UAT-10 厂家直发

创建厂家直发销售明细，记录供应商发货、送达和设备标识。确认本店各仓库库存不变，订单、安装和设备追踪完整。

### UAT-11 数据导入与打印

使用脱敏样表执行导入预览、错误修正和分批提交，最终数据数量一致；销售单和安装单按样张打印，客户信息完整且不包含成本利润。

## 7. 数据上线计划

1. 盘点 1 万条以内现有纸单、Excel、微信记录中实际需要迁移的范围。
2. 确定商品和客户唯一识别规则，清理重复数据。
3. 在测试环境试导入并生成差异报告。
4. 店主抽查商品、客户、余额和历史订单。
5. 确定切换时点，冻结旧表格写入并做最终增量导入。
6. 上线后保留旧资料只读备查，不立即删除。

如果历史记录极不规范，优先迁移商品、当前库存、未完成订单和有售后价值的客户，不为了“全部导入”制造大量无法核实的错误数据。

## 8. 上线与回退

上线前：

- 确认生产配置、HTTPS、管理员账号和最小权限。
- 完成全量备份，验证数据库迁移可执行。
- 执行自动化测试和关键 UAT。
- 通知用户切换时间和旧记录停止写入时间。

上线后：

- 重点观察登录失败、接口错误、库存冲突、备份和磁盘空间。
- 每日抽查订单与库存流水，直到业务稳定。
- 缺陷按数据错误、安全问题、阻断操作和一般体验排序。

回退原则：

- 应用版本可以回退，但已执行的数据结构变更必须使用经过验证的迁移方案。
- 发生库存或订单数据一致性问题时，先暂停相关写操作并保全日志，不直接手工改数据库。
- 回退后记录未同步业务，由负责人按单据补录或冲销。

## 9. 主要风险与应对

### 录入负担过高

应对：用真实单据删减字段，默认值和自动计算替代重复输入；观察草稿废弃率和线下补记情况。

### 数据初期不可信

应对：上线前盘点当前库存；所有调整留原因；试运行期间每日抽查库存和订单。

### 范围持续扩大

应对：所有新增需求必须说明替代做法和优先级；不改变 P0 目标的增强进入 P1 清单。

### 外出网络不稳定

应对：第一版保留草稿和失败重试，不做高风险离线库存同步；根据实际失败频率决定是否投入离线能力。

### 单人掌握系统

应对：保留部署、备份、恢复和账号管理文档；至少让另一位负责人完成一次恢复演练。

## 10. 当前建议的下一步

1. 提供仓库名称、特殊库存实例、序列号标签、脱敏 Excel 和打印样张。
2. 根据这些样例确认字段与状态，随后制作手机端和电脑端关键页面原型。
3. 原型确认后冻结第一版 P0 范围，再进入 M1 工程初始化。

当前开发基线已经包含单门店、多仓库、厂家直发、逐台设备追踪、多次收款和欠款管理。进入数据库开发前只需补齐仓库清单、商品标识规则、脱敏数据样表、收款方式和打印样张；若以后增加多门店或在线交易，再重新评估权限与架构。
